Runnel benchmark history

Runnel optimization history with separate native and three-node competitor comparison suites.

Interpret series according to their recorded measurement boundaries. Runnel and JetStream include acknowledgement paths; Kafka and Redpanda consumer figures currently measure fetch throughput without per-message application acknowledgement. CPU efficiency means messages per broker CPU-second, and memory is the peak broker memory sampled during the selected scenario. The dedicated Runnel history and older native-comparison measurements are shown as separate suites; competitor suites remain separate as well. Consumer latency is not reported by every native benchmark client, so an empty latency chart is an unavailable measurement rather than a zero.

Charts show each run's median as a dot, a five-run rolling median as a line, and the observed repetition range as a band when available. Tail-latency charts use a logarithmic y-axis so large outliers remain visible without flattening normal results.
